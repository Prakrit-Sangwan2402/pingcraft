--------------------------------------------------------------------------------
1. INTRODUCTION & LOGIN (0:00 – 0:45)
--------------------------------------------------------------------------------
[ACTION: Show Sign In page on https://pingcraft-gamma.vercel.app]

"Hi everyone, I'm Prakrit Sangwan, and today I'm showing you PingCraft, an API
health monitoring and incident management platform I built using the MERN stack.

APIs often fail silently, and developers usually don't know until users complain.
PingCraft solves this by pinging endpoints in the background, measuring real-time
latency, and automatically triggering incidents when services go down.

You can create a new account here with email and password, which uses bcrypt hashing
on the backend. Since I already have an account, let me log in."

[ACTION: Type credentials and click 'Sign In']

"Once I log in, you can see my username right here at the top corner.
Behind the scenes, the backend generates a signed JWT token on login. The frontend
stores this token in React state and local storage, and attaches it as a Bearer
header to authenticate every API call."


--------------------------------------------------------------------------------
2. DASHBOARD & INSTANT PROBE WITH SSRF DEFENSE (0:45 – 1:40)
--------------------------------------------------------------------------------
[ACTION: Show Cockpit Dashboard]

"Here on the main dashboard, we get an instant overview: total monitors, operational
services, degraded endpoints, and active outages.

Before setting up background jobs, PingCraft has an Instant Probe feature to test
any endpoint immediately without saving it to the database."

[ACTION: Click 'Instant Probe' button]

"Because users can enter any URL, we built in SSRF protection to stop attackers from
probing internal servers.

Let's test it: if I try to ping localhost or a private cloud IP..."

[ACTION: Enter http://localhost:5000/api/health and click 'Execute Probe']

"...it's blocked immediately by our backend validator before opening any connection.

Now let's test a real public endpoint, like GitHub's API."

[ACTION: Enter https://api.github.com and click 'Execute Probe']

"And in just a few milliseconds, we get the exact response time, HTTP status code,
and payload size."


--------------------------------------------------------------------------------
3. MONITOR METRICS & TELEMETRY (1:40 – 2:30)
--------------------------------------------------------------------------------
[ACTION: Close modal, click on a monitor to open Monitor Detail]

"To monitor an endpoint continuously, you can click 'Add Monitor' and set your URL,
check frequency—like every 15 or 30 seconds—and failure thresholds.

Opening an active monitor shows detailed telemetry:
- Rolling 24-hour and 7-day uptime percentages.
- A latency trend chart over time, along with the 95th percentile (p95) response time.
- And down here is the ping history log, showing the exact timestamp and status for
  every probe.
- You can also pause any monitor anytime with one click."


--------------------------------------------------------------------------------
4. INCIDENT WAR ROOM & AUTO-RECOVERY (2:30 – 3:20)
--------------------------------------------------------------------------------
[ACTION: Click 'Incident War Room' in top navbar]

"Next is the Incident War Room.

When an endpoint fails consecutive checks, it flips from Degraded to Outage, and the
system automatically creates an incident record. We use database constraints to make
sure a monitor never gets duplicate active incidents.

From here, responders can track the incident: moving it from Triggered, to
Investigating, to Mitigating, while leaving timeline notes."

[ACTION: Click an active incident and click 'Acknowledge & Investigate']

"Every update is logged in an audit timeline.

Best of all: when the service recovers and passes checks again, PingCraft automatically
resolves the incident, logs the total downtime, and marks the service operational
without any manual intervention."


--------------------------------------------------------------------------------
5. PUBLIC STATUS PAGE & TECH STACK (3:20 – 4:10)
--------------------------------------------------------------------------------
[ACTION: Open Public Status Page tab /#/status/api-status]

"For end users and customers, PingCraft provides a Public Status Page. This page is
completely public, requires no login, reveals no sensitive tokens, and shows
real-time uptime and active incidents.

[ACTION: Switch to Terminal showing passing test results]

Under the hood, the project is built on the MERN stack:
- React 18, Vite, and Tailwind CSS deployed on Vercel.
- Node.js and Express deployed on Render.
- MongoDB Atlas with Mongoose for indexing and data storage.
- A background scheduler running parallel synthetic probes.

To ensure reliability, the backend includes an automated test suite. Right here in
the terminal, all 35 tests covering SSRF security, metrics, and incident workflows
are passing cleanly.

Both the live link and GitHub repository are in the description. Thank you!"
