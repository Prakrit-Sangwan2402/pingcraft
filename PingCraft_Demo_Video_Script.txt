PART 1: INTRODUCTION & AUTHENTICATION (0:00 – 0:45)
--------------------------------------------------------------------------------
[ACTION: Screen is on https://pingcraft-gamma.vercel.app at the Sign In page.]

"Hello everyone, my name is Prakrit Sangwan, and today I’m presenting PingCraft —
an end-to-end synthetic API health monitoring and incident response platform built
on the MERN stack.

The problem this solves is simple: APIs frequently suffer silent degradation,
latency spikes, or sudden 500 errors, and developers usually don't find out until
users start complaining. PingCraft continuously pings critical endpoints, measures
precision latency, detects outages using configurable failure thresholds, and
provides public status pages for transparency.

On the authentication screen here, any user can register for a new account with
email and password, which uses bcrypt hashing and JWT tokens on the backend.
Since I already have an account set up, let me log right in."

[ACTION: Enter email/password and click 'Sign In'.]

"Once logged in, you can see my username displayed right here at the top corner
along with our session controls."


--------------------------------------------------------------------------------
PART 2: COCKPIT DASHBOARD & INSTANT PROBE WITH SSRF DEFENSE (0:45 – 1:45)
--------------------------------------------------------------------------------
[ACTION: Land on the main Monitors Cockpit dashboard.]

"This is the Monitors Cockpit. At the top, we have system-wide KPIs: Total Monitors,
Operational count, Degraded, Down, and Paused services.

Before setting up scheduled background jobs, PingCraft includes an Instant Probe
tool for real-time diagnostics. Let me open it."

[ACTION: Click 'Instant Probe' button. Modal pops up.]

"This lets engineers test an endpoint on demand. But more importantly, this is
where our custom SSRF Protection Engine kicks in. Because users can submit arbitrary
URLs, attackers often try to target internal infrastructure.

Let's test that. If I try to probe http://localhost:5000 or an AWS internal
metadata IP like 169.254.169.254..."

[ACTION: Type http://localhost:5000/api/health and click 'Run Probe'.]

"...the request is immediately blocked by our backend DNS validator before any
outbound packet is dispatched.

Now let’s test a legitimate public API, like https://api.github.com."

[ACTION: Type https://api.github.com and click 'Run Probe'.]

"Within milliseconds, we get the HTTP 200 OK status, the exact response time
measured using Node's monotonic performance.now() clock, response payload size,
and the sanitized response headers."


--------------------------------------------------------------------------------
PART 3: MONITOR CONFIGURATION & TELEMETRY ANALYTICS (1:45 – 2:45)
--------------------------------------------------------------------------------
[ACTION: Close Instant Probe modal. Click 'Add Monitor' or 'Load Starter Endpoints'.]

"Now let's configure a continuous synthetic monitor. Clicking Add Monitor opens
our configuration panel.

Here we can set:
- The HTTP method: GET, POST, PUT, DELETE, or HEAD
- Custom request headers and JSON payloads
- Check interval — for example every 15 or 30 seconds
- And our SLA thresholds: consecutive failures required to trigger an outage,
  and consecutive successes required to auto-recover.

Let's open one of our active monitors to view its deep analytics."

[ACTION: Click on any monitor card to open the Monitor Detail page.]

"Here in the detail view:
- We have rolling 24-hour and 7-day uptime percentages computed via our dedicated
  backend metrics service. If there’s not enough data, it honestly reports 'No data'
  rather than faking 100%.
- This responsive chart uses Recharts to plot our response latency trends over time,
  alongside the nearest-rank 95th percentile (p95) latency.
- Down below is the paginated ping log, showing UTC timestamps, exact HTTP status
  codes, and latency for every single probe.
- We can also pause the monitor anytime with one click, which immediately excludes
  it from the scheduler workload."


--------------------------------------------------------------------------------
PART 4: INCIDENT STATE MACHINE & AUTO-RECOVERY (2:45 – 3:45)
--------------------------------------------------------------------------------
[ACTION: Click on the 'Incidents' tab in the top navigation.]

"Next is the Incident War Room. When an endpoint fails its consecutive failure
threshold, the monitor flips from DEGRADED to DOWN, and PingCraft's deterministic
state machine automatically triggers a new incident.

Our backend enforces database-level partial unique indexes to guarantee that a
monitor can have at most one active incident at a time, preventing alert fatigue
and duplicate incident spam.

Responders can track the full lifecycle: moving an incident from TRIGGERED to
INVESTIGATING with responder notes, then to MITIGATING."

[ACTION: Click on an incident, update status to 'INVESTIGATING', and show timeline.]

"Every action is logged in an append-only audit timeline showing who did what and
when.

Even better: once the monitored service comes back online and meets its recovery
threshold, the background scheduler automatically resolves the incident, logs the
total downtime duration, and restores the monitor to OPERATIONAL without needing
manual intervention."


--------------------------------------------------------------------------------
PART 5: BRANDED PUBLIC STATUS PAGE (3:45 – 4:15)
--------------------------------------------------------------------------------
[ACTION: Click 'Status Page' in navigation, or open /#/status/api-status in a new tab.]

"For external communication, PingCraft provides clean, branded Public Status Pages.

This route is completely unauthenticated and accessible to customers or stakeholders.
It displays real-time operational status, component-level health, and ongoing
incident notices without leaking any internal tokens or sensitive server configuration."


--------------------------------------------------------------------------------
PART 6: TECH STACK & AUTOMATED TEST SUITE (4:15 – 4:45)
--------------------------------------------------------------------------------
[ACTION: Switch window to VS Code or Terminal showing 'npm test' output.]

"Under the hood, the entire architecture is built using:
- React 18 and Tailwind CSS on the frontend with Vite, deployed live on Vercel.
- Node.js and Express on the backend, hosted on Render.
- MongoDB Atlas with Mongoose for scalable document storage with compound indexing.
- Monotonic high-resolution timers and a background scheduler running parallel
  non-blocking probes.

Quality assurance is verified through an automated Jest and Supertest suite. As you
can see right here in the terminal: all 35 unit and integration tests covering SSRF
validation, p95 mathematics, incident state machine transitions, and API workflows
are passing with zero errors.

Both the live web application on Vercel and the open-source GitHub repository are
linked in the description. Thank you for watching!"
