PART 1: INTRODUCTION, DESIGN PHILOSOPHY & AUTHENTICATION (0:00 – 0:50)
--------------------------------------------------------------------------------
[ACTION: Screen is on https://pingcraft-gamma.vercel.app at the Sign In page.]

"Hello everyone, my name is Prakrit Sangwan, and today I’m presenting PingCraft —
an end-to-end synthetic API health monitoring and incident response platform built
on the MERN stack.

The problem PingCraft solves is critical: APIs frequently suffer silent degradation,
latency regressions, or intermittent 500 errors, and engineering teams often don't
find out until users complain. PingCraft continuously probes critical endpoints,
measures high-precision latency, triggers automated incident lifecycles when SLA
thresholds breach, and publishes public status bulletins for transparency.

Before logging in, notice the visual identity here: we deliberately stepped away
from generic, AI-generated dark-blue dashboard templates. Instead, PingCraft uses an
'Industrial Editorial' design language — inspired by precision lab equipment,
warm paper typography, stone dividing rules, and technical measurement instruments.

On this authentication screen, any new user can register with an email and password,
which uses bcrypt password hashing with salt rounds on our backend. Since I already
have my account set up, let me log right in."

[ACTION: Enter email and password, then click 'Sign In'.]

"Once logged in, you can see my username displayed right here at the top corner
alongside our session controls.

Technically, how this works: upon successful login, our Express backend generates a
signed JSON Web Token containing the user's ID and display name. Our React
AuthContext decodes this payload, keeps it in state and local storage, and
attaches it as a Bearer authorization header to every subsequent API request while
rendering the verified session right here."

PART 2: COCKPIT DASHBOARD & INSTANT PROBE WITH SSRF DEFENSE (0:50 – 1:50)
--------------------------------------------------------------------------------
[ACTION: Land on the main Monitors Cockpit dashboard.]

"This brings us to the Monitors Cockpit.

Notice the composition:
- At the top, we have system-wide KPIs: Total Monitors, Operational, Degraded,
  Outages, and Paused services, rendered with tabular monospace numbers and
  earthy status tones — muted forest green for healthy endpoints, ochre for
  degraded, and brick red for active outages.
- Instead of bulky rounded cards, the monitors are organized into an editorial
  register table with clean stone dividing rules.

Before setting up recurring background probes, PingCraft includes an on-demand
Instant Probe diagnostic instrument. Let me open it."

[ACTION: Click 'Instant Probe' button. Modal pops up.]

"This modal lets engineers immediately probe an endpoint. But more importantly,
this is where our custom SSRF Protection Engine comes into play. Because synthetic
monitors accept arbitrary URLs, malicious users often try to query internal networks
or cloud metadata.

Let's test our defense. If I try to target loopback at http://localhost:5000 or
an AWS metadata IP like 169.254.169.254..."

[ACTION: Type http://localhost:5000/api/health and click 'Execute Probe'.]

"...the request is immediately blocked by our backend DNS and subnet validator
before any socket connection is opened.

Now let’s test a legitimate public endpoint, like https://api.github.com."

[ACTION: Type https://api.github.com and click 'Execute Probe'.]

"Within milliseconds, we get an industrial diagnostic readout: HTTP 200 OK, the
exact latency measured with Node's monotonic performance.now() clock, payload size
in bytes, and sanitized headers."

PART 3: MONITOR REGISTRY & DEEP TELEMETRY ANALYTICS (1:50 – 2:50)
--------------------------------------------------------------------------------
[ACTION: Close Instant Probe modal. Point to 'Add Monitor' and then click a monitor row.]

"Creating a continuous synthetic monitor is straightforward: clicking 'Add Monitor'
lets us configure the HTTP method, request headers, payload body, check interval
like every 15 or 30 seconds, and failure SLA thresholds.

Let’s click into one of our active monitors to view its deep telemetry page."

[ACTION: Click on a monitor row to open the Monitor Detail page.]

"Here in the Monitor Detail view:
- The page heading is styled with an editorial serif typeface, pairing clean visual
  restraint with dense engineering data.
- Up top, we have rolling 24-hour and 7-day uptime percentages computed by our
  dedicated backend metrics service. Notice that if an endpoint lacks sufficient
  historical data, it honestly displays 'No data' rather than displaying a false 100%.
- Below that is our Latency Trend chart on a soft ivory canvas with a vermilion trace
  line, plotting latency history alongside our calculated 95th percentile (p95)
  latency using the nearest-rank mathematical method.
- Further down is the ping telemetry log, displaying precision UTC timestamps, HTTP
  status codes, response times, and failure categories for every probe.
- We also have a one-click pause toggle up here, which instantly excludes this monitor
  from the background scheduler workload."


--------------------------------------------------------------------------------
PART 4: INCIDENT WAR ROOM & STATE MACHINE (2:50 – 3:45)
--------------------------------------------------------------------------------
[ACTION: Click on the 'Incident War Room' tab in the top contrast navigation bar.]

"Next, let’s inspect the Incident War Room.

When an endpoint fails its consecutive failure threshold — for example, 2 consecutive
failed checks — the monitor automatically transitions from DEGRADED to OUTAGE,
and PingCraft's deterministic state machine creates an incident record.

Our MongoDB database enforces partial unique compound indexing, ensuring that a
monitor can have at most one active incident at any time, preventing alert spam.

Responders can manage the incident lifecycle through a structured workflow:
moving from TRIGGERED to INVESTIGATING with root-cause notes, then to MITIGATING,
and finally to RESOLVED."

[ACTION: Click an active incident, type a note, transition to INVESTIGATING, show timeline.]

"Every status update appends an event to this immutable audit timeline, recording
the actor, timestamp, and message.

Even better: when the service recovers and passes consecutive probes meeting its
recovery threshold, PingCraft's background scheduler automatically resolves the
incident, logs the exact downtime duration in seconds, and restores the monitor
to OPERATIONAL without needing human intervention."

PART 6: TECH STACK & AUTOMATED TEST SUITE (4:15 – 4:45)
--------------------------------------------------------------------------------
[ACTION: Switch screen to terminal / VS Code displaying 'npm test' output.]

"Under the hood, the entire architecture is built on the modern MERN stack:
- Frontend: React 18, Vite, and Tailwind CSS with custom editorial design tokens,
  deployed live on Vercel.
- Backend: Node.js and Express, hosted on Render.
- Database: MongoDB Atlas with Mongoose, utilizing compound indexes for fast
  telemetry queries and partial indexes for incident integrity.
- Engine: A non-blocking background scheduler running concurrent synthetic probes
  with monotonic high-resolution latency timers and an SSRF security shield.

To ensure production-grade reliability, the codebase is backed by a comprehensive
test suite. As you can see right here in my terminal: all 35 unit and integration
tests in Jest and Supertest — covering the SSRF defense engine, p95 percentile
calculations, the incident state machine, and end-to-end API workflows — are
passing with zero errors.

Both the live Vercel application and the GitHub repository are linked in the
description. Thank you for watching!"
